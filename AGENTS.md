# Development notes

- Use `docker compose -f docker-compose.base44.yml up -d --build`. Source is bind-mounted; Vite reloads the frontend and Node watches only server.ts. Watching the full import graph loops when Vite updates its dependency cache.
- bun.lock uses lockfile version 2 and needs Bun 1.4.2 (1.3.14 cannot read it). Compose installs the pinned manager and dependencies on startup without changing the lockfile.
- The Express dev middleware attaches HMR to its own HTTP server. Port 3000 serves `/` and unhashed `/src/main.tsx`; both are checked by the container healthcheck.
- Local generation lives in src/utils/studioAdapter.ts and src/studio-core. No AI API key is needed, no provider routes run, and former provider components and SDK dependencies are removed. Do not reconnect them for local planning.
- Preserve all unscoped legacy browser storage keys byte-for-byte. New work uses injected workspaceStorage adapters under scene_script_workspace_v2 with separate guest, Firebase UID and explicit recovery namespaces. This covers draft/library/generated output/project identity/backups/templates/reusable brief/preset choices. Never infer ownership of old unscoped content or merge it into the first signed-in account. Theme/starter-rotation behavior stays unchanged. Do not clear or migrate user data during theme work.
- Firebase configuration, auth provider and optional cloud sync are independent of local planning; leave them unchanged unless requested. useCloudSession owns the stable story-loading auth observer: read only on actual UID transitions, discard late results after UID/generation changes or unmount. AuthBar does not subscribe. App gates identity resolution and remounts the entire workspace on account/guest/recovery changes. Cloud copies use a separate per-account cache and duplicate loads preserve state references.
- Additional production details (cameraDirection, atmosphereDetails, continuityNotes, scene1Beat/scene2Beat/scene3Beat) are optional strings preserved by studioAdapter normalization. The adapter adds literal shared direction to every output and scene-specific beats/handoffs to paired canvases; do not put future scene beats in the shared contract. Legacy records need no migration.
- CharacterPlanner edits the draft roster and the same three scene beats as ProductionDetails. Character links use scene numbers (1–3), so editing a beat cannot orphan them. characterContinuity.ts carries the last linked emotional state forward, omits unlinked actions, and validates optional roster data in version 1 snapshots. Generate updates the shared production snapshot; Story Bible and saved prompts show that snapshot, not unsaved character edits.
- TemplatesWorkspace persists validated template cards in scene_script_templates_v1; JSON downloads are portable copies and imports never upload files. storyTemplates.ts scopes structures/archetypes, validates versioned files via the snapshot validator, assigns fresh cast ids on apply, and merges notes without deleting existing text. New-project loading persists a full draft/production/output/manual-edit backup in scene_script_project_backups_v1 before switching; failed backup writes block switching. Restore also backs up the project being left. These libraries are browser-local, not cloud-synced. Merge keeps output until regeneration.
- Checks: `docker compose -f docker-compose.base44.yml exec -T web bun run lint` and `docker compose -f docker-compose.base44.yml exec -T web bun run build`. Browser checks should exercise Quick Seeds, Generate Story Prompt, editable output, local Save/Library Load, six canvases and Story Bible. Back up and restore existing browser data around temporary test saves.

- Production build combines Vite output with an esbuild ESM `server.js` bundle in the repository root. Keep `server.js` next to `dist/`; `npm start` runs this bundle directly. Run `npm run test:production` after building to verify key-free startup and removed APIs. Unknown `/api` paths return JSON 404 before SPA fallback.
- Use `createLocalId` for new browser-local IDs. It preserves UUIDv4 format and uses Web Crypto `getRandomValues` when `randomUUID` is unavailable on an HTTP LAN preview; do not migrate existing IDs.
- `base44/config.jsonc` is a site-only hosting configuration for the existing Firebase-backed app, not a request to scaffold or replace its backend. `npm run build:base44` emits `dist-base44/` with browser-only private Drive backup. Connect is a separate per-user Firebase Google reauthentication requesting drive.file; Google tokens stay in memory and API enablement/live consent must be verified separately. Only use approved site-only publication; do not run all-resource Base44 deploy, enable shared Drive connectors, or replace Firebase. Preserve the account/session guards around local Save and keep Drive disabled in older-data recovery.

- Older browser data is preserved at original keys. The first-load notice offers raw JSON export and an explicitly confirmed recovery workspace. Recovery falls back to originals for reads but writes/tombstones only its own namespace; it never uploads or auto-assigns to an account. Recovery closes on an auth-generation change. Cloud Save, Drive panel and enqueue are disabled there. Account cache separation is not encryption or access control against someone operating the same browser profile.

- Cloud-project deletion is a separate explicit, irreversible review flow. Preserve `glam-camera-action` v1 provenance eligibility, fresh `gca_v1_` UUID cloud snapshots, authoritative Firestore IDs, per-document transaction rechecks, original-session guards, and the same-tab save/review barrier. Never auto-tag/delete unmarked legacy or other-app records. Confirmed-absent IDs invalidate only the original account's derived cloud cache (including after unmount), never independent local saves, drafts, backups, recovery originals, profile/auth, chat or Drive. Cache failures and cross-tab/device limits must remain explicit. See docs/CLOUD_PROJECT_DELETION.md and synthetic SDK-boundary tests; never test deletion against live Firebase without separate authorization.
